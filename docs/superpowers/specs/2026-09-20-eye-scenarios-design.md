# skillstotraineyes: scenario catalog, difficulty levels, hidden-object posts

Date: 2026-09-20. Status: design approved in chat, pending spec review.

## Goal
Make the eye-skills niche produce effectively unlimited, harder scenarios from data, not code changes. Inputs: skilldrills.online CSV exports (name + rule only) and a hidden-object image idea.

## Decisions
| # | Decision |
|---|---|
| 1 | Two content types in one niche (`skillstotraineyes`): drill Reels and hidden-object image posts. |
| 2 | Drill modes: `watch` (passive follow) and `challenge` (task, countdown, reveal). Click-only source drills (Flick, Recoil, Strafe) are reframed as `watch`. |
| 3 | Hidden-object: static 1080p IG feed image, no video. Images generated by the existing `pipeline/image_gen.py` chain from detailed prompts. The answer is **never** revealed; viewers guess in comments. No target-presence check (user's call). |
| 4 | Scenarios are invented by the LLM via `llm_router.call_llm`, like `script_gen` for other niches. Code screens output (claims, repeats) as `wording.py` does. |
| 5 | Every CSV drill becomes a family with a short descriptive catalog entry. The LLM refers to the catalog and picks any at random; the video is built from that pick. |
| 6 | Same IG account (`skillstotraineyes_ig`) for both types. Needs an image-post path in `instagram_upload.py`; Drive/schedule flow reused. |
| 7 | Five difficulty levels, badge shown at video start: Easy 100%, Medium 60%, Hard 25%, Expert 10%, God Mode 1%. Wording exact as given ("GOD MODE · 1% can pass this"). The percentages are labels, not measured statistics. |
| 8 | Difficulty is a **score**, not a speed dial. Knobs: speed, ball count, ball size (tiny and huge both score), decoy similarity, path visibility, interruptions, occlusion, memory length, hidden-object scene density. |
| 9 | Both a budget generator (seeded random knob mix landing in the level's score range) and named presets (e.g. "Swarm", "Bullet") that carry their own level and override the generator. |
| 10 | Image posts reuse Drive `pending/` (no new folder or secret). The manifest marks the item as an image post. The cron fetches it from Drive and uploads it to the existing temp host (`_upload_to_temp_host`, MIME type made dynamic instead of hardcoded `video/mp4`) to get the public URL Instagram needs. New `upload_image_post()` in `instagram_upload.py` reuses the container-create/poll/publish code, sending `image_url` with no `media_type=REELS`. Drive public links rejected: unreliable for Instagram's fetcher. |

## Components
- `skillstotraineyes/catalog.json`: one entry per family (name, rule, mode, knob ranges, presets). Source: the four CSVs.
- `skillstotraineyes/difficulty.py`: knob scores, level ranges, seeded generator, badge text.
- `skillstotraineyes/drills.py` (extend): new families as seeded templates returning draw ops. Path pursuit (sine, zig-zag, triangle, infinity, slow Lissajous), split-screen, vertical-step, spatial-shift, ghosting suppress, then memory and cognitive.
- `skillstotraineyes/wording.py` (extend): LLM picks from the catalog; writes hook, caption, scenario details.
- `pipeline/instagram_upload.py` (extend): feed image publish.
- Hidden-object generation: scene and target invention via LLM, prompt built to bury the target, image via `image_gen`.

## Guards
- The unambiguous-answer rule (`tracking`) holds at every level.
- Uniqueness gate keys on (family, level, knob mix).
- The medical-claim screen stays; the disclaimer is appended in code.
- Every clip stays under 30s.

## Phases
1. Catalog, `difficulty.py`, path-pursuit families and their tests.
2. Hidden-object image posts: LLM scenario, `image_gen`, IG image publish, tests.
3. Memory and cognitive families.

## Tests
- Knob mixes stay inside their level's score range; scores monotonic across levels.
- Determinism asserted on sim state, not pixels (existing convention).
- Slow tests cover the real render (ffprobe 1080x1920/30fps, audio == video length).

## Verified risks (found by reading the code, 2026-09-20)

| # | Risk | Mitigation |
|---|---|---|
| R1 | The niche sets no `human_policy`, so it defaults to `"never"`. `sanitize_no_humans()` would strip "sniper"/"soldier" from a hidden-object prompt and push it into the negative — the target would never be drawn. | Set `"human_policy": "none"` on the niche in `settings.json`. Assert it in a test. |
| R2 | FLUX providers cap near 60 words / 77 CLIP tokens. A long "bury the target" prompt loses the target — the measured failure in `build_positive_prompt`. | Hidden-object prompts are capped at 55 words and the scene/target clause comes first. A test enforces the cap. |
| R3 | Pollinations returns 576×1024 for a 1080×1920 request. `ensure_render_size()` upscales, which cannot restore detail — fatal for a find-the-object image. | Reject any provider image whose short edge is under 1024px and fall through to the next provider. Prefer Gemini, which honours the requested size. |
| R4 | Instagram's image endpoint takes JPEG. `_sniff_extension()` returns png/jpg/webp depending on the provider. | Convert to JPEG before upload. |
| R5 | `sim.make_sim()` raises on infeasible combinations (`ball_r*4 > arena_r`, placement needs `2.2*ball_r` spacing, `speed <= arena_r*2`). A high-difficulty knob mix such as 10 balls at r=74 crashes the run. | `difficulty.fits()` screens the mix before `make_sim`; the builder re-rolls on failure and never raises. |
| R6 | `tracking()` raises `RuntimeError` when 60 seeds fail its `min_gap(0) >= 3.0` reveal gate. Dense high-difficulty mixes will hit that. | Keep the best-gap candidate and use it instead of raising; scale the required gap with the ball count. A test asserts the gap stays ≥ 2.0 at every level. |
| R7 | `test_drill_shape` asserts every drill runs 15–30s. `saccade` already lands near 27.5s, so a difficulty badge that adds its own segment would breach 30s. | The badge is drawn inside the existing hook window. It costs zero seconds. |
| R8 | `pick_family()` reads `FAMILIES` while `build()` reads `BUILDERS`. A new entry added to one and not the other is either unreachable or a `KeyError`. | The catalog becomes the single source; a test asserts every catalog entry's builder exists. |
| R9 | `process_schedule()` hardcodes `video.mp4` and calls `upload_all(video_path=...)`, which always routes Instagram to `upload_reel`. | The manifest carries `media_type`; `upload_all` routes on it. Absent, it defaults to video, so every existing caller is unaffected. |
| R10 | The LLM writes the hidden-object caption and could give away the answer. | Screen the caption for position words (`top left`, `behind`, `under`, …) and fall back to the default on a hit. |
